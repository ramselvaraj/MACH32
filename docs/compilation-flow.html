The linker problem

What failed

GCC added its default startup file named crt0.o. MACH32 already had a startup file and a reset handler.

Startup file: Code that prepares the processor before main() runs.
Reset handler: The first MACH32 function that runs after processor reset.

The default startup file expected __bss_start__, __bss_end__, and end symbols.

The MACH32 linker script uses _sbss, _ebss, and other bare-metal symbols instead.

The linker could not find the default symbols. It stopped before it made the final program.

What fixed it

The -nostartfiles option stops GCC from adding its default startup files.

MACH32 now uses only startup_stm32f446xx.s for processor startup.

The startup code calls __libc_init_array(). Newlib uses this function to run static constructors.

Static constructor: A function that the C runtime can run before main().

The removed default files also supplied the _init hook. MACH32 now supplies a no-operation _init hook.

The linker script now defines the constructor table boundaries that __libc_init_array() uses.

The central idea

The ARM core does not read C files, object files, ELF files, or Makefiles.

The ARM core reads machine instruction bytes from addresses in Flash memory.

The build tools create those bytes. ST-LINK places those bytes at the required Flash addresses.

The linker connects all object files

Linker: A tool that connects compiled parts and assigns final memory addresses.

The linker resolves these real connections:

main.o
  ├─ calls mach32_board_init()       → nucleo_f446re.o
  ├─ calls mach32_gpio_init()        → gpio.o
  └─ calls mach32_gpio_write_pin()   → gpio.o

gpio.o
  └─ calls mach32_rcc_ahb1_periph_clock_enable() → rcc.o

startup_stm32f446xx.o
  ├─ calls SystemInit()              → system_stm32f4xx.o
  ├─ calls __libc_init_array()       → Newlib Nano
  └─ calls main()                    → main.o
Newlib Nano: A small C runtime library for embedded systems.

The --specs=nano.specs option selects Newlib Nano. The --specs=nosys.specs option supplies basic bare-metal stubs.

System call stub: A placeholder for an operating-system service that bare-metal code does not have.

The current program does not call file input or file output functions. It does not need working operating-system services.

The linker script assigns memory addresses

Linker script: A file that defines memory regions and controls section placement.

The script defines the STM32F446RE memory:

Flash

0x08000000 through 0x0807FFFF

Flash keeps code and constant data without power.

RAM

0x20000000 through 0x2001FFFF

RAM stores writable data and the stack while power is present.

Stack: RAM that stores temporary function data, saved registers, and return addresses.

The real linked program uses these addresses:

ItemAddressPurpose
Vector table0x08000000Provides startup and interrupt addresses.

The .bss section uses eight bytes from 0x20000004. These zero bytes do not need space in the raw binary.

9

ST-LINK writes the BIN file into Flash

ST-LINK: The debugger and programmer on the Nucleo board.
Programmer: A tool that writes machine code into microcontroller Flash.

The Makefile runs this command:

st-flash write build/01_led_blink/firmware.bin 0x08000000

ST-LINK completed these real operations:

  1. Erased Flash sector 0.
  2. Wrote 11,056 bytes at 0x08000000.
  3. Read the programmed data.
  4. Verified that the programmed data matched the BIN file.
  5. Started execution in Thumb mode.
Verification: A comparison that confirms that Flash contains the requested bytes.

The BIN file does not contain its start address. The command supplies the address 0x08000000.

The Cortex-M4 starts at the vector table

After reset, the processor reads the first two 32-bit values in Flash:

Flash addressStored valueProcessor action
0x080000000x20020000Load the initial stack pointer.
0x080000040x08002791Start Reset_Handler in Thumb state.
Stack pointer: A processor register that identifies the current top of the stack.

The reset-handler symbol is at 0x08002790. Bit zero in the vector value selects Thumb state.

The bit does not change the instruction address. The processor fetches the first instruction from 0x08002790.

11

Reset_Handler prepares the C environment

The startup assembly runs this sequence:

  1. Load 0x20020000 into the stack pointer.
  2. Call SystemInit().
  3. Copy initialized data from Flash to RAM.
  4. Write zero into the complete .bss section.
  5. Call __libc_init_array().
  6. Call main().

SystemInit() enables access to the FPU. It also sets the vector table address to 0x08000000.

This LED example does not call mach32_rcc_system_clock_config(). The processor continues to use the 16 MHz internal clock.

Internal clock: A clock signal that a circuit inside the microcontroller generates.

The initialized .data bytes must move into RAM because C code can change those variables.

The .bss section must start with zero values because the C language requires that state.

12

main() changes the physical LED

The application uses this real call path:

main()
  |
  +-- mach32_board_init()
  |     +-- enable GPIOA and GPIOC clocks in RCC->AHB1ENR
  |
  +-- mach32_gpio_init(&led)
  |     +-- select GPIOA
  |     +-- configure PA5 as a push-pull output
  |     +-- configure low output speed
  |     +-- disable pull resistors
  |
  +-- loop forever
        +-- write PA5 high through GPIOA->BSRR
        +-- run the delay loop
        +-- write PA5 low through GPIOA->BSRR
        +-- run the delay loop
RCC: Reset and Clock Control enables the clock for each peripheral.
GPIO: General-Purpose Input/Output controls digital microcontroller pins.
Push-pull output: An output that can actively drive a pin low or high.
BSRR: A GPIO register that changes output bits with one atomic write.
Atomic write: One hardware operation that another operation cannot interrupt halfway.

Writing the lower BSRR bit sets PA5. Writing its upper BSRR bit resets PA5.

PA5 connects to the green LD2 LED on the Nucleo board. The changing voltage makes the LED blink.
